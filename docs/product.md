# 产品范围与功能（v1）

本文是当前产品范围的唯一说明，回答“做什么、为什么、做到什么程度”。技术契约与架构另见实现阶段文档。

## 1. 产品定义

Nota 是一个 AI 语音便签 / 会议助手：一个入口，接住从一句提醒到一场会议；短的直接办成待办 / 提醒，长的先出纪要再确认事项。

快记和会议不是两个产品，而是同一条管线的两种使用强度：输入长度不同，AI 输出的密度不同；用户不需要先选模式。

v1 先做文字输入；语音 / 音频 / ASR 是后续能力，不改变本文的产品行为。

## 2. 目标用户与场景

**目标用户**：每天在会议、通话、聊天里产生大量口头信息和承诺的中文知识工作者；早期 50 位种子用户。

**核心场景**：
- 会后：把一段会议文字变成摘要、重点和候选待办。
- 随时：一句话创建提醒或待办。
- 事后：用对话修改、删除、完成之前创建的事项。

**非目标（v1）**：多人协作、团队权限、企业合规、真实日历同步、硬件、Android、语音识别。

## 3. 用户故事

### S0 登录 / 注册

**故事**：作为用户，我输入邮箱和密码；邮箱没注册过就自动创建账号并登录，注册过就校验密码，错了显示错误。

**验收**
- 新邮箱：创建账号并进入主界面。
- 已注册邮箱 + 正确密码：进入主界面。
- 已注册邮箱 + 错误密码：显示“邮箱或密码不正确”，不进入。
- 邮箱统一小写、去空格；密码最少 6 位。
- 邮箱包含 `vip`（不区分大小写）视为 VIP：Free 每天 10 次，VIP 不限次。
- 登录状态在重启后保留；可以退出登录。
- v1 不做邮箱验证、找回密码、第三方登录。

### S1 快记：创建提醒

**故事**：我说“提醒我两个小时后去游泳”，希望两小时后收到通知。

**验收**
- AI 解析相对时间，按当前时间算出绝对时间。
- 创建一条提醒；摘要显示“今天 23:56 提醒你去游泳”这类绝对时间。
- iOS 发本地通知；Web 在页面打开时提示。
- 算 1 次额度。
- 创建后可以对话修改或删除。

### S1b 快记：创建待办

**故事**：我说“记一下，明天买牛奶”，希望有一条待办。

**验收**
- 创建待办；没有具体时间就不发通知。
- 摘要说明“已记录”。
- 算 1 次额度。

### S2 复杂多事项

**故事**：我说“提醒我下周末去爬山，中午 12 点提醒我网购路餐，朋友约我下午 5 点在约定地点碰面，我过去差不多要一个小时，提前提醒我出发”，希望 AI 拆成正确的多条提醒。

**验收**
- 把“下周末 / 下周六”换算成具体日期，并在摘要里写出。
- 创建 12:00 买路餐、16:00 出发、17:00 碰面三条事项。
- 16:00 是 17:00 减 1 小时车程的推断，摘要要写明。
- 所有时间必须是未来；不能落成今天或过去。
- 只算 1 次额度。
- 用户可以说“出发改到 15:30”或“删掉买路餐”继续修正。

### S3 会议文字 → 纪要 / 重点 / 候选待办

**故事**：我粘贴一段会议文字，希望看到摘要、重点和候选待办。

**验收**
- 返回 title、summary、3–7 条 keyPoints、候选 actions。
- 候选 actions 带负责人（如果说了）、时间（如果说了）、原话依据。
- 默认不自动创建提醒 / 待办；只作为“待确认”。
- 算 1 次额度。
- 长文本有长度上限；超限给可读提示。

### S4 确认候选待办

**故事**：我在会议详情里点某条候选待办，或说“把第 2 条加入待办”，希望它变成我的事项。

**验收**
- 点按钮创建待办 / 提醒；有 dueAt 就排通知。
- 按钮操作不扣额度；对话操作算 1 次。
- 创建后能追溯到来源对话 / 纪要。
- 批量确认（“把和我有关的都加上”）列为 P1。

### S5 对话纠错

**故事**：创建后我发现不对，说“改到 15:30”“删掉买路餐”或“游泳完成了”，希望在对话里直接改。

**验收**
- AI 先找到对应事项；找到多条或指代不清时先问“你是指哪一条”。
- 支持改时间 / 标题、删除、标记完成。
- 删除 / 完成 / 修改后，本地通知同步取消或重排。
- 明确说“删掉”可以直接删；指代不清先确认。
- 每次用户消息算 1 次额度。

### S6 歧义澄清

**故事**：我说“下周末去爬山”但没说周六还是周日，希望 AI 先问清楚，而不是猜错。

**验收**
- AI 返回一个具体问题（“下周六 11 月 14 日还是周日 11 月 15 日？”）。
- 在用户回答前，不创建事项。
- 用户回答后继续创建，摘要里写最终日期。
- 不影响时间的歧义可以带假设创建，并在摘要里标注。

### S7 额度 / VIP

**故事**：Free 用户一天第 11 次提交时，希望看到额度用尽；VIP 用户希望不限次。

**验收**
- Free 每天 10 次；第 11 次被拒，显示重置时间。
- VIP 不限次；界面显示 VIP 标记。
- 一次用户消息算 1 次；点按钮确认事项不算。
- 失败（模型 / 网络）不扣额度。
- 重试同一条消息不重复扣。

### S8 历史

**故事**：我想翻看之前的对话和事项。

**验收**
- 历史按时间倒序展示对话 / 笔记。
- 打开能看到消息、摘要、重点、候选待办、已创建事项。
- 事项显示 open / done / deleted 状态。
- 按时间 / 关键词筛选列为 P1。

### S9 退出 / 切换账号

**故事**：我想退出登录或换一个账号。

**验收**
- 退出后清登录状态，回到登录页。
- 退出时取消本机已排的通知，避免上一个账号的提醒继续弹。
- 再次登录能恢复该账号的历史和事项。

## 4. 功能清单

### 4.1 账户与会员

- 邮箱 + 密码登录；新邮箱自动注册。
- VIP 按邮箱识别；Free 10 次 / 天，VIP 不限次。
- 退出登录；不做邮箱验证、找回密码、第三方登录。

### 4.2 对话与输入

- 一个文字输入框；短命令和长文本都走这里。
- 多轮对话；AI 可以反问，用户可以继续纠正。
- 对话历史可回看。

### 4.3 AI 理解与输出

- 输出 title、summary、可选 keyPoints、候选 actions。
- 不做 quick / meeting 硬分类；按内容决定输出结构。
- 明确命令直接执行；长文本里推断的任务只作为建议。
- 展示 AI 调用过哪些能力（工具轨迹），便于用户信任。

### 4.4 事项

- 创建提醒（带时间）和待办（可不带时间）。
- 修改标题 / 时间；删除；标记完成。
- 事项状态：open / done / deleted。
- 事项与来源对话 / 纪要关联。

### 4.5 会议纪要

- 长文本生成摘要、重点和候选待办。
- 候选待办带负责人、时间、原话依据。
- 不自动创建；用户确认后进入事项。

### 4.6 历史

- 对话 / 纪要列表；详情。
- 事项状态可查。
- 筛选 / 搜索 P1。

### 4.7 额度

- Free 10 次 / 天；VIP 不限次。
- 一次用户消息 = 1 次；按钮操作 = 0 次。
- 失败不扣；重试不重复扣。

### 4.8 通知

- iOS 本地通知。
- Web 在页面打开时应用内提示。
- 删除 / 完成 / 退出登录时同步取消。

## 5. 优先级

**P0（v1 必须）**
- S0 登录 / 注册。
- S1 / S1b 快记。
- S2 复杂多事项。
- S3 会议文字 → 纪要 / 重点 / 候选待办。
- S4 确认候选待办。
- S5 对话纠错（改 / 删 / 完成）。
- S6 歧义澄清。
- S7 额度 / VIP。
- S8 历史。
- S9 退出 / 切换账号。

**P1（有时间再加）**
- 历史搜索 / 筛选。
- 批量确认候选待办。
- 冲突提示（新建事项与已有安排冲突时提醒）。
- 导出 / 分享纪要。
- 重复提醒。
- Web 通知增强。
- 语音 / ASR。
- 真实日历同步。

**不做**
- Android、硬件、多人协作 / 团队权限、企业合规、订阅支付、邮箱验证 / 找回密码、离线模式。

## 6. 关键流程

### 6.1 首次使用

1. 打开 App / Web，进入登录页。
2. 输入邮箱和密码。
3. 新邮箱自动注册；老邮箱校验密码。
4. 进入主界面，看到输入框和历史。

### 6.2 快记

1. 输入“提醒我两个小时后去游泳”。
2. AI 解析时间，创建提醒。
3. 页面显示摘要和绝对时间。
4. iOS 到点发本地通知；Web 在页面打开时提示。

### 6.3 会议

1. 粘贴会议文字。
2. AI 生成纪要、重点和候选待办。
3. 用户点选或说“把第 2 条加入待办”。
4. 生成事项；有时间的排通知。

### 6.4 纠错

1. 用户说“出发改到 15:30”。
2. AI 找到对应事项并修改。
3. 页面确认；本地通知重排。
4. 删除 / 完成同理。

### 6.5 额度

1. Free 用户当天第 10 次后额度用尽。
2. 第 11 次提交被拒，显示重置时间。
3. VIP 用户不触发限额。

## 7. 状态与错误

- 空状态：没有历史时，引导用户说第一句话或粘贴一段会议文字。
- 加载：AI 处理中显示“整理中”，禁止重复提交。
- 失败：模型 / 网络失败显示可读错误，保留输入，可重试；失败不扣额度。
- 超额：显示“今日额度已用完”和重置时间；VIP 不显示。
- 未登录 / 登录过期：回到登录页。
- 指代不清：AI 先问，不执行删除 / 修改。

## 8. 待定问题

- 对话模型：一个连续对话，还是每个会议 / 主题一个 thread？
- 删除确认：按钮删除是否要二次确认？
- Pro 定价：$6.99/月是否沿用？VIP 是否等同 Pro？
- 纪要可编辑：summary / keyPoints 是否允许用户改？
- 历史搜索：P1 是否包括“上次和张总聊的报价”这类问答？
- 多端：同账号多设备是否同步通知？v1 明确不做。
- 输入上限：会议文字最大长度是多少？
- 隐私：会议内容上传 AI 服务的提示与数据保留策略。

## 9. 术语

| 术语 | 含义 |
|---|---|
| 快记 | 短输入，直接生成待办 / 提醒 |
| 会议纪要 | 长输入，生成摘要、重点和候选待办 |
| 候选待办 | AI 推断出来、等用户确认的事项 |
| 事项 | 待办或提醒 |
| 对话 | 用户与 Nota 的多轮交互 |
| VIP | 不限次数的会员；当前用邮箱含 vip 识别 |
