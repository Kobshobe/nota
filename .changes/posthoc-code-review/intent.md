# Intent: 对已落地 MVP 做补审

## Problem

首版服务端和客户端是在旧流程下实现的：没有 worktree 隔离，也没有独立 review。自动化门禁和真实 e2e 覆盖了主路径，但不能替代对契约、事务、并发、错误路径和客户端状态的独立审查。

## Outcome

- 独立审查者分别审查服务端、客户端和跨端契约/集成。
- 输出 P0/P1/P2；P0/P1 修复或记录明确理由。
- 修复后的 diff 由审查者复核；全量门禁和真实 e2e 通过。

## Constraints

- 审查者只读，不改代码、不提交、不杀进程。
- 修复若改变系统行为，另建变更链，不把审查和功能改动混在一起。
- 不扩大 v1 范围；P1 产品能力仍不在本次范围。
