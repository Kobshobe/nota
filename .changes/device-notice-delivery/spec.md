# Spec: 设备会议通知的送达

## Behavior

- App 登录且在前台时，每 20 秒检查一次，App 从后台回到前台时也立即检查一次。
- 检查方式：取日常对话的 thread，拿最后一条 `role = system` 的消息；消息 id 与上次看到的不同才处理。
- 有新通知时：调本地通知（iOS 通知中心）弹一条「Nota 会议已整理」+ 消息内容；Web 用页面内提示条；同时刷新线程列表，若正停在该对话则重新加载。
- 首次检查只记录当前最后一条为基线，不弹通知；退出登录后清空基线。
- 未登录、没有日常 thread、请求失败都静默跳过，不打断用户操作。
- 后端无改动；不使用 APNs / Web Push。

## Alternatives considered

- APNs：锁屏也能收到，但需要开发者账号、证书和设备 token 注册，Web 还要另一套。
- SSE / WebSocket：实时性更好，但服务端要加长连接与心跳，v1 没做。
- 只靠时间线消息：用户不刷新就不知道，等于没有提醒。

## Areas of concern

- 最多 20 秒延迟；App 在后台或被系统挂起时完全不检查。
- 每 20 秒两个请求，演示规模可以接受，用户多了要换成推送或 SSE。
- 如果 20 秒内连续来两条通知，只会弹最新一条。
