# Intent: 持久化工具轨迹与候选事项关联

## Problem

刷新 thread 后，工具轨迹消失，用户看不到 Agent 之前调用过什么。候选事项的“已加入”状态只存在当前会话内，重新打开 thread 会再次出现按钮，可能重复创建同一事项。事项的 `dueAt` 也只能设置或修改，不能清空。

## Outcome

- `GET /threads/{id}` 的消息携带工具轨迹，刷新后仍可展示。
- 事项记录可追溯到来源消息和候选序号；按钮确认过的候选在重新打开时显示为已加入，并阻止重复创建。
- 编辑事项时可以把时间清空，事项变成无时间的待办。

## Constraints

- 兼容已有数据：旧事项的来源字段为空，不要求回填。
- 契约、baseline、服务端迁移和客户端模型同步更新。
- 不改变 v1 的额度规则：按钮操作仍然不扣额度。
