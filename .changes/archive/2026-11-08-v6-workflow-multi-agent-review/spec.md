# Spec: 多代理工作流与独立 review

## Behavior

- `AGENTS.md` 规定四个角色：协调者、生产者、消费者、审查者；实现者不得自审。
- 两个并行写者必须各用一个 `wt` worktree；契约只有一个作者；生产端先合，消费端从合并后的 main 重开。
- 非平凡变更的每个实现端必须有一个只读 review 子代理，按 `file:line` 输出 P0/P1/P2；协调者分诊后才提交/合并。
- P0 必须在合并前修复；P1 修复或记录延期；P0/P1 修复后的 diff 必须由同一审查者复核。
- 子代理不 commit/push；协调者统一提交、合并两端、推送和归档变更链。
- `docs/workflow.md` 记录命令、顺序、review 清单、门禁和端到端约定。

## Alternatives considered

- **只靠 `make check-all`**：验证不了契约之外的业务语义、事务边界和 UI 状态。
- **实现者自审**：同一上下文会重复同样的假设；不能替代独立视角。
- **所有改动都开 worktree + review**：文档/小改成本过高；只对并行写者和非平凡变更强制。

## Areas of concern

- 审查者可能把建议写成实现；必须明确只读、不改文件。
- 独立 review 需要额外时间；用 P0/P1/P2 控制范围，避免无限返工。
