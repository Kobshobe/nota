# Spec: 可读的工具调用日志

## Behavior

- 每次 `POST /threads/{id}/messages` 触发的 Agent 运行写三类日志：`agent 运行开始`（threadId、userMessageId、输入字数）、每个工具的 `▶`/`✔`/`✘` 行（工具名、脱敏后的参数、结果摘要、耗时）、`agent 运行结束`（工具次数、总耗时）。
- 工具行的人类可读正文写在日志的 `msg` 上；结构化字段只保留 `tool`、`durationMs`、`isError` 这类可过滤的短值，不把参数和结果序列化成 JSON。pretty 终端隐藏这些字段，JSON 模式保留。
- 参数按工具语义渲染：`标题=「买牛奶」 类型=待办 时间=2026-11-08 10:00`；控制字符和换行压成空格，文本超过 80 字截断并加 `…`，列表里每条标题不超过 30 字。
- 结果按工具语义渲染成一句话：`已暂存 new_1（待办）`、`命中 2 条：买牛奶、周报`、`已暂存结果：回复、标题、2 条候选`。
- 失败渲染成 `失败：A reminder requires dueAt`，不吞掉原始错误文本；运行级失败日志带脱敏后的错误原因和未结束的工具名。
- 每个请求收尾打一行 `POST /api/threads/{id}/messages → 200 2650ms`，`/api/health` 不打；不再输出 Fastify 默认的多行请求对象。
- 服务端终端日志默认 `pretty`（人类可读单行 + 缩进字段）；`LOG_FORMAT=json` 时输出 pino 原始 JSON，`LOG_LEVEL` 控制级别，两者都能从 `.env` 读取，非法 `LOG_FORMAT` 在启动时抛错。
- 客户端工具轨迹弹窗以「参数」「结果」两段中文键值行展示，`kind`/`status` 翻译成中文，`dueAt` 按本地时区显示，列表按下标编号；未知字段按原名展示，不再出现 JSON 文本。

## Alternatives considered

- **只在客户端做可读化**：终端里仍然看不到工具调用，排查线上问题时缺少一手信息。
- **日志里直接 `JSON.stringify(args)`**：可读性差，且长文本会把一行日志撑爆。
- **给每个工具写独立的日志格式函数**：六个工具各写一套，重复且容易漂移；按「参数键 + 结果键」统一渲染更省。
- **默认输出 JSON，靠 `pino-pretty` 管道自己做**：用户要的就是默认可读，让每次启动都记得加管道是错的。
- **客户端弹窗保留 JSON 折叠视图并加开关**：v1 没有要读原始 JSON 的场景，加开关只是多一个状态。

## Areas of concern

- 新增 `pino-pretty` 依赖，仅用于输出格式；JSON 模式不依赖它。
- 日志正文是中文，机器消费请用 `LOG_FORMAT=json` 读字段。
- 客户端字段名翻译表需与工具参数保持同步；未知键按原名兜底，不会崩。
