# Spec: 发出第一条内容才创建会议

## Behavior

- 主对话右上角会议按钮只做导航：进入 `/meeting/new` 空白会议页，不调用创建接口。
- 空白会议页标题「新会议」，显示会议的空状态和同一个输入条；发送时先 `POST /threads`（不填标题）再 `POST /threads/{id}/messages`，成功后用会议对话替换当前页。
- 发送失败时停在空白页展示错误；会议已创建则复用该 id 重试发送，不会重复建会。
- 主对话不再渲染「最近会议」横条。已创建的会议按 `createdAt` 与消息一起排进对话时间线，显示为「会议 + 标题 + 时间」卡片，点卡片进入该会议。
- 空会议（没有任何消息）在时间线里同样显示卡片；卡片标题为空时显示「未命名会议」。
- 会议页、事项页、账号页行为不变。

## Alternatives considered

- **点按钮就建会、进入后再补内容**：正是要修的问题，空会议会污染数据。
- **保留「最近会议」横条，只是不显示空会议**：仍需要 message 计数接口；用户要的是卡片出现在对话里。
- **新建会议弹窗填标题**：上一轮已经去掉，用户要「直接能输入」。

## Areas of concern

- 时间线卡片按 `createdAt` 排序，会议日期与消息日期混排，可能夹在两条消息之间；这是「卡片出现在对话里」的直接结果。
- 创建成功但发送失败会留下一条空会议，v1 没有删除接口。
- 空白页没有真正的「取消并丢弃」语义，返回即放弃，未发送就不会创建。
